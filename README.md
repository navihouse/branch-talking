# BRANCH · 树状分支对话

卡片式 AI 对话应用。每条回复是一张卡片，卡片右上角有两组按钮：

**语义按钮**

- **`+` 子卡片**：在卡片内展开输入框，输入提示词继续推进这个话题，子卡片生成在**主卡片的正下方**。
- **`~` 平行卡片**：先在卡片中**选中一段文字**，再点 `~`，会弹出输入框让你填写提示词，然后基于选中内容生成平行卡片，显示在**主卡片的左右两侧**（多张时左右交替）。选中文字时，选区**上方会自动浮出一个 `~` 按钮**（贴近屏幕顶部时改为浮在下方），点击即可直接创建，不遮挡选中内容。

**窗口控件**（模仿 Windows 窗口）

- **`─` 最小化**：折叠为**小正方形卡片**（96×96），卡片主题显示在方块内部上方；此时右上角**不显示任何图标**，**点击该卡片**即可还原到最小化前的尺寸（状态会保存）。主卡片 / 子卡片 / 平行卡片行为一致。
- **`▢` 最大化**：卡片放大为全屏浮层，再点一次或按 `Esc` 还原。
- **`✕` 关闭**：删除该卡片及其全部下游分支（会二次确认）。

**画布与视角（无限画布）**

- 卡片树渲染在一层通过 CSS `transform: translate3d()` 平移的画布上，**不受文档流边界限制**，可以向上下左右**任意方向无限平移**（不再靠内边距撑空间，所以不会出现「只能往一边拖」或内容被裁切）。
- **进入页面 / 刷新后会自动把当前对话内容居中**显示在屏幕中央（`centerView()`），不会偏左或偏右。
- **按住空白处拖动**即可平移视角；**滚轮**上下平移，`Shift+滚轮` / 横向滚轮左右平移。
- 新增卡片时会**补偿布局位移**（`panX/panY` 反向偏移），父卡片视觉上不跳动，也不会与其他卡片重叠；随后自动把新卡片移入视野。
- 生成回复时视角会自动跟随正在输出的卡片；你一旦手动拖动 / 滚动，跟随会暂停 2.5 秒。

**卡片尺寸**

- 主卡片宽 830px；子卡片及其后续子孙卡片统一宽 760px——即**子卡片只比主卡片小一点，且子卡片的子卡片与子卡片等宽**，不会逐层变窄。
- **多个子卡片左右并排**：同一主卡片的多个子卡片横向排在**同一条水平线上**（平行排列），而不是上下堆叠。
- **间距与下游规模挂钩**：每个子卡片与左侧相邻卡片的间距 = `34px` 基础间距 + 它自己的下游卡片数 × `10px`（上限 `+150px`），因此**下游越多的分支离主卡片越远**，一眼就能看出哪条分支更“重”。该计算参考了 d3.tree 中 `separation` 按子树规模分配间距的思路。
- 平行卡片保持窄幅（236px）置于主卡片两侧；其**内部**的子卡片仍纵向排列，避免把侧栏撑得过宽。

**其它**

- **卡片层级清晰**：子卡片在主卡片下方、位于卡片元素之外；平行卡片在主卡片两侧，都不会被包进主卡片里。
- **绿色连线**：卡片之间用绿色细线连接，走线为平滑的贝塞尔曲线，并叠加**流动的虚线动画**形成波动感（主卡片→子卡片为纵向波浪，主卡片→平行卡片为横向拱形）。`prefers-reduced-motion` 下自动关闭动画。
- 生成子卡片 / 平行卡片时，会把祖先卡片（**含直接父卡片**）的提问与回复**原文**按 `user` / `assistant` 轮次依次带上，既保证上下文连贯，又能复用 DeepSeek 的上下文缓存。
- **为缓存优化了消息排列**：固定的长系统提示在最前、动态内容（本次指令、选中片段）压到最后，前缀从第 0 个 token 起逐字节稳定。详见下方「上下文缓存」。
- 每张卡片底部显示 **token 用量**：`↑ 输入 N（缓存命中 M） · ↓ 输出 K`，方便观察 DeepSeek 上下文缓存命中情况。
- 输出长度由 `DEEPSEEK_MAX_TOKENS` 限制（默认 2048）；**思考模式默认关闭**（`DEEPSEEK_THINKING=disabled`），避免思考 token 吃光输出预算导致正文为空。若开启思考，卡片会以可折叠的「思考过程」区块展示，并有截断提示。
- 支持 **Markdown** 与 **LaTeX 公式**：行内 `$...$`、`\(...\)`，独立公式 `$$...$$`、`\[...\]`（KaTeX 已本地化，无需联网 CDN）。
- **可自定义主题**：主卡片 / 子卡片 / 平行卡片颜色（`#RRGGBB`）+ 背景纯色或图片（可调透明度），配置写入 `package.json`。
- 回复通过本地 Node 代理调用 **DeepSeek**（OpenAI 兼容接口），流式打字机输出。
- API Key 只保存在服务端 `.env`，前端代码里不出现。

## 目录结构

```
index.html          页面结构
styles.css          终端风深色样式
app.js              卡片树 / 流式渲染 / localStorage 持久化
server.mjs          零依赖 Node 服务：静态托管 + /api/chat 流式代理
vendor/katex/       本地 KaTeX（katex.min.js / css / woff2 字体）
theme-bg.png        主题背景图片（导入后自动生成，路径记录在 package.json 的 theme 里）

.env.example        配置模板
```


## 启动

1. 打开项目根目录的 `.env`，填入你的 DeepSeek Key：

   ```
   DEEPSEEK_API_KEY=sk-xxxxxxxx
   ```
2. 启动服务（无需 npm install，零依赖）：

   ```
   npm start
   ```

   或直接：

   ```
   node server.mjs
   ```
3. **必须**在浏览器打开 `http://localhost:3000`。

> ⚠️ 不要直接双击 `index.html` 打开（`file://`）。那样页面能显示，但连不上后端，AI 不会回复。
> 页面顶部会自动检测并给出提示。

> 🔑 **`.env` 优先级最高**：它会**覆盖**系统环境变量 / opencode 等注入的同名 `DEEPSEEK_API_KEY`。
> 修改 `.env` 后**必须重启** `node server.mjs` 才生效。启动日志和页面顶部横幅都会显示
> **密钥来源**（`.env 文件` / `系统环境变量`）与密钥尾号，可用来确认用的是哪一个 Key。

## 排查：输入提示词后没有回复

页面顶部横幅会直接告诉你原因：

| 现象                                  | 原因与解决                                                                                |
| ------------------------------------- | ----------------------------------------------------------------------------------------- |
| 横幅提示`无法连接后端服务`          | 没启动服务，或不是通过`http://localhost:3000` 访问                                      |
| 横幅提示`未检测到 DEEPSEEK_API_KEY` | 编辑`.env` 填写 Key 后**重启**服务                                                |
| 卡片底部 token 为 `↑ 输入 0`          | 请求未发出，检查后端与网络                                                                |
| 卡片显示`（模型没有返回内容）` 或 `输出 = 上限` | 思考 token 占满了输出上限。保持 `DEEPSEEK_THINKING=disabled`（默认），或调大 `DEEPSEEK_MAX_TOKENS` |
| 卡片出现红框`HTTP 401`              | Key 无效或余额不足，去[platform.deepseek.com](https://platform.deepseek.com/api_keys) 检查 |
| 卡片出现红框`HTTP 429`              | 触发限流，稍后重试                                                                        |
| 卡片出现红框`DeepSeek 接口返回 ...` | 网络/接口异常，按提示文字排查                                                             |
| 卡片一直转圈后报超时                  | 网络到`api.deepseek.com` 不通，检查代理/网络                                            |

## 使用

- 底部输入框输入提示词，`Enter` 发送（`Shift+Enter` 换行），生成第一张卡片。
- **按住空白处拖动**可以平移视角；滚轮上下滚动。
- 在任意 AI 卡片上：
  - 点 `+` → 填写提示词 → 生成**子卡片**（在主卡片正下方）。
  - 用鼠标**选中卡片中的文字** → 选区上方会浮出 `~` 按钮，点它即可（或点卡片右上角的 `~`）→ 填写提示词 → 生成**平行卡片**（在主卡片左右两侧）。
  - `─` 最小化（图标全部隐藏，点卡片还原）、`▢` 全屏、`✕` 删除。
- 所有卡片自动保存在浏览器 `localStorage`，刷新后仍在；右上角「清空」可重置。

## 主题

点击右上角 **「主题」** 打开设置面板，可自定义：

| 项目 | 支持形式 |
| --- | --- |
| 背景颜色 | `#RRGGBB` 十六进制 |
| 背景图片 | 导入 PNG / JPEG / GIF / WebP / BMP（上限 8MB），**透明度可调**（0–100%） |
| 主卡片颜色 | `#RRGGBB` 十六进制 |
| 子卡片颜色 | `#RRGGBB` 十六进制 |
| 平行卡片颜色 | `#RRGGBB` 十六进制 |

- **卡片颜色只接受 `#FFFFFF` 形式的十六进制值**（支持 `#abc` 简写自动展开为 `#AABBCC`），非法输入会保留原值。
- 选择浅色卡片底色时，**前景文字会自动切换为深色**（按相对亮度计算），保证可读性；代码块、边框、分隔线也会基于底色自动派生。
- **主题保存在项目根目录 `package.json` 的 `theme` 字段**：

  ```json
  "theme": {
    "background": { "color": "#0B0C0E", "image": "", "imageOpacity": 0.35 },
    "cardRoot": "#111317",
    "cardChild": "#111317",
    "cardParallel": "#111317"
  }
  ```

  导入的背景图片会保存为项目根目录的 `theme-bg.png`（或 `.jpg` 等），`theme` 里只记录路径，避免把 Base64 塞进 `package.json`。

- 相关接口：`GET /api/theme` 读取、`POST /api/theme` 保存（带图片时 POST 体中传 `imageData` 的 data URL）。
- 主题同时缓存在浏览器 `localStorage`，打开页面立即生效，再与服务端同步。

## 服务端日志

`node server.mjs` 的终端会对**每一次请求**打印一行统计，便于排查：

```
[chat] model=deepseek-flash 思考=关 msgs=2 finish=stop 输入=72 缓存命中=0 输出=967 思考token=0
```

- `finish=length` 表示**被 `DEEPSEEK_MAX_TOKENS` 截断**（正文可能不完整）。
- `思考token` 很大但 `输出` 约等于上限，说明思考过程吃掉了输出预算。
- `缓存命中` 是 DeepSeek 前缀缓存命中的输入 token 数。

## 上下文缓存（为什么有时 `缓存命中=0`）

DeepSeek 的上下文缓存是**自动的前缀缓存**，规则（官方）：

- 以 **64 token 为一个存储单元，不足 64 token 不会被缓存**；
- **只有从第 0 个 token 起完全一致的前缀**才算命中，中间相同不算；
- 每次请求会在「用户输入结束」和「模型输出结束」各留下一个**缓存前缀单元**，后续请求完全复用才命中；
- 缓存闲置数小时到数天后会被清理。

本项目的消息排列就是围绕这套规则设计的：

| 场景 | 复用的前缀 | 预期命中 |
| --- | --- | --- |
| 新话题的第 2 次及以后 | 整段固定的长系统提示 | 数百 token |
| 根卡片 → 子卡片 | 根卡片那次请求的完整内容 | 覆盖根卡片一轮 |
| 同一父卡片下的两个兄弟分支 | `系统提示 + 祖先回合 + 父卡片回复` | 命中父回复（大块） |
| 父 → 子 → 孙 | 子请求的「模型输出结束」缓存单元 | 命中子一轮 |
| 平行卡片 → 平行卡片 | 上一张平行卡片的完整一轮（提问 + 回复） | 命中上一张平行卡片 |

> 实现要点：平行卡片的提问是按模板拼出来的（带选中片段），
> 因此发送请求与回放祖先**共用同一个 `composeUserMessage()` 函数**，
> 保证同一条 user 消息逐字节一致。否则下游分支的前缀会在该位置分叉，命中量骤减。

**注意：新话题的第一次请求必然是 0 命中**——没有更早的请求共享它的前缀，这是缓存机制的物理限制，不是 bug。

> 如需进一步提升命中率，可以把 `app.js` 里的 `SYSTEM_PROMPT` 写得更长（更多固定规范），
> 让每次请求共享的前缀更大；但不要把任何「每张卡片都不一样」的内容拼进系统提示，
> 那会让前缀从第 0 个 token 起就分叉，导致命中率骤降。

## 配置项（.env）

| 变量                  | 默认值                       | 说明                                                                       |
| --------------------- | ---------------------------- | -------------------------------------------------------------------------- |
| `DEEPSEEK_API_KEY`  | 无                           | 必填，DeepSeek API Key                                                     |
| `DEEPSEEK_MODEL`    | `deepseek-flash`           | 模型名                                                                     |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 接口地址（OpenAI 兼容） |
| `DEEPSEEK_MAX_TOKENS` | `2048` | 单次回复最大输出 token 数，防止输出过长 |
| `DEEPSEEK_THINKING` | `disabled` | 思考模式开关。默认关闭直接出正文；设为 `enabled` 会先输出思考过程，**很耗 token** |
| `DEEPSEEK_REASONING_EFFORT` | `high` | 仅 `DEEPSEEK_THINKING=enabled` 时生效，可选 `low` / `high` / `max` |
| `PORT` | `3000` | 本地端口 |
| `HOST`              | `127.0.0.1`                | 监听地址。默认仅本机可访问；改成`0.0.0.0` 会让局域网他人也能调用你的 Key |

## 安全说明

- **API Key 只存在服务端**：浏览器前端代码里没有任何 Key，Key 由 `server.mjs` 从环境变量 / `.env` 读取。
- **`.env` 已被 `.gitignore` 忽略**，不会提交到 GitHub。仓库里只保留无密钥的 `.env.example`。
- **默认只监听 `127.0.0.1`**：局域网内其他设备无法访问，避免额度被盗用。
- **拒绝跨站请求**：`/api/chat` 会校验 `Origin`，其他网站无法通过浏览器调用你的本地接口。
- **静态文件防目录穿越**：仅允许访问项目目录内、非点号开头的文件（`.env`、`.git` 无法被读取）。
- **主题写入受限**：`POST /api/theme` 仅本机可调用（校验 `Origin`），只允许写入 `package.json` 的 `theme` 字段；背景图片仅接受 PNG/JPEG/GIF/WebP/BMP，上限 8MB（**不接受 SVG**，避免脚本注入）。
- **安全响应头**：所有响应带 `Content-Security-Policy`（`script-src 'self'`，禁止外链脚本与内联脚本）、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`frame-ancestors 'none'`，降低 XSS / 点击劫持 / MIME 嗅探风险。
- **前端不做危险操作**：无 `eval`、无 `new Function`、无 `child_process`；所有渲染先做 HTML 转义，主题图片 URL 经过白名单校验后才写入 CSS。

### 上传 GitHub 前

1. 执行 `git status`，确认列表里**没有 `.env`**（当前仓库已由 `.gitignore` 排除）。
2. 若曾误提交过 `.env`，仅删除文件无效，必须去 DeepSeek 控制台**吊销并重建 Key**。
3. 第三方代码：`vendor/katex/` 为 KaTeX（MIT），其许可证已保留在 `vendor/katex/LICENSE`。
4. 建议为项目本身补一个 `LICENSE`（如 MIT / Apache-2.0）——没有许可证的公开仓库默认为「保留所有权利」，他人无法合法使用。
5. 背景图片 `theme-bg.*` 会随主题一起进入仓库，确认它不包含隐私内容后再提交。

## 常见问题

- **页面提示「服务器未配置 DEEPSEEK_API_KEY」**：编辑 `.env` 填好 key 后重启 `node server.mjs`。
- **`DeepSeek 接口返回 401`**：key 无效或余额不足。
- **`DeepSeek 接口返回 429`**：触发限流，稍后重试。
- **刷新后某张卡片显示中断**：生成过程中刷新了页面，重新生成即可。
